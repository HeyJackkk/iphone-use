# 测试认证与用户接管

出现密码、PIN、解锁码或验证码页面时，先判断测试授权、凭据来源和工具能力，不再一律要求用户手动输入。空控件树或黑色截图不足以证明正在认证；先区分锁屏、镜像占用、自绘内容与通道故障。

## 已授权的自动化测试

用户已明确要求测试指定 App、账号或设备的认证流程，并提供凭据或指定其测试来源时，可以在该范围内自动输入密码、PIN、解锁码及验证码。同一会话已确认的授权继续有效，不为每个认证字段重复确认。来源可以是用户指定的 fixture、私有凭据文件、secret store 或测试验证码接口；缺少具体来源时询问必要信息，不猜测或扩大到无关账号、短信及邮件。

1. 根据当前页面确认目标 App、账号与字段。正常可编辑字段可用 `pua_type_text` 输入指定的测试凭据；测试验证码可从已授权来源读取或生成。
2. 自动认证前暂停预览，减少凭据展示。授权包含登录 / 解锁提交时可完成对应提交；不将认证授权扩展为发送消息、付款或删除数据。
3. 不在回复、报告、截图、日志或版本库里复述凭据。密码字段不要求明文回读；通过认证后的页面、状态或测试断言验证结果。
4. 凭据错误、验证码过期、限流、锁定风险或动作结果不确定时停止该次尝试。先核对实际状态，不猜码、盲目重放或无限重试。
5. 自动认证成功后直接恢复预览并继续已授权测试，无需等待用户再次回复「已完成继续」。设备解锁后必须重验 READY；App 登录后核对目标页，READY 本身不证明 App 已登录。

### 技能许可与当前工具能力

技能修改不会改变运行时能力：当前 `pua_type_text` 仍拒绝 `SecureTextField`，锁屏时常规动作仍返回 `phone_locked`，公开 PUA 工具没有解锁码接口。遇到这些技术限制时准确报告缺少的能力，并转为用户接管；不能把修改技能描述成这些限制已解除，也不临时使用裸 WDA 请求绕过守卫。需要测试这些路径时，应另行实现和验证受授权范围约束的运行时支持。

真实 Face ID / Touch ID、Apple 信任确认或系统要求的本人操作不能用文字输入代替，工具不能完成时交给用户。

## 先区分阻塞层

| 当前证据 | 处理 |
| --- | --- |
| App 的登录 / 密码 / 验证码提示 | 有明确测试授权、指定凭据及支持的字段时自动认证；缺少授权 / 凭据或工具不支持时才请求用户接管。READY 不证明 App 已登录。 |
| `phone_locked` 或实际手机锁屏 | 当前公开工具不支持自动输入解锁码，交给用户解锁；未来有明确授权且已验证的解锁能力时可自动测试，完成后仍需 READY。 |
| Face ID / Touch ID 或本人信任确认 | 当前真机能力无法替代本人确认，按实际提示交接。 |
| `local.pid.0` / `pua_foreground_unavailable` / XCTest Code 41 | 依照 setup skill 恢复 PUA 通道；不能当作 App 密码错误。只有系统确实要求信任或认证时才让用户完成对应操作。 |

## 交接时说明什么

仅在授权 / 凭据缺失、工具能力不足、用户选择手动或系统要求本人操作时使用以下接管流程。先调用 `pua_screen(action="pause")`，停止预览并清空画面，再给接管提示。显式 App 认证暂停不会因为 READY / open 自动解除。`phone_locked` 已自动记录 `device_locked` 并暂停，无需再显式 pause；实际解锁通知后，成功 READY 自动解除这一次锁屏暂停。用户自己点击刷新也是主动恢复预览的请求；刷新确认解锁后可解除点击时的 App / unknown 暂停，模型不能代点这个 App 专用按钮。新暂停发生在检查期间时不会被旧检查清除。旧版没有原因的暂停按 unknown 保留。接管期间不轮询帧、截图或用户输入。

必须调用宿主可用的提问功能提示用户接管，不只在普通消息或 final 中写“完成后回复继续”。提问说明实际 App、阻塞步骤、用户要完成的动作和随后继续的工作；第一个选项固定为 **「已完成继续」**，第二个可用「暂时无法完成」。问题只询问是否已完成手机上的操作，不收集密码、PIN 或验证码。

在 Codex Default 模式优先调用 `functions.request_user_input_async`，例如当前明确显示 Face ID 时：

```json
{
  "questions": [{
    "title": "当前 App 需要 Face ID 验证。请在 iPhone 上完成认证并停留在目标页面；完成后选择「已完成继续」，我会接着读取剩余明细。",
    "options": ["已完成继续", "暂时无法完成"]
  }]
}
```

按当前证据替换 App、认证方式和后续工作；手机锁屏则要求用户亲自解锁并保持唤醒。宿主提供其他提问工具时按其实际 schema 调用，首个选项文字仍保持「已完成继续」；不要为调用提问功能切换模式。如果当前宿主确实没有可调用的提问功能，才使用文字提示并明确保留“等待用户认证”的未完成状态。

异步提问会立即返回，这不是用户完成通知。保持问题待答，等待用户实际提交选项或明确回复；预选项、工具返回、等待时间经过和没有答复都不能当作完成。可以继续整理已经取得的结果或其他不依赖手机认证的工作，不能恢复手机调用；没有独立工作时等待用户输入，不用重复提问或手机轮询来消耗等待时间，不将整项任务标记完成。

手动接管只描述实际认证方式和页面，不收集凭据，不猜测密码、PIN 或绕过生物识别。已授权测试凭据输入按前面的自动化流程处理，普通 TextField 不再因为用于密码而一律要求手动输入。凭据不写入报告、日志或版本库，也不临时生成绕过工具守卫的脚本。

保留当前 App / 页面、已取得内容、已执行步骤、未完成项与动作执行边界，不要求为保存进度先逐步验收，也不记录认证凭据。接管期间暂停该 iPhone 的操作、观察和截图；可以整理已有结果及进度，不能轮询用户输入。Face ID 失败、要求改用密码或验证码过期时，让用户按手机实际提示处理，不能连续触发验证或反复重启 App / PUA。

## 手动接管完成后继续

只有收到用户实际选择「已完成继续」或明确说明认证已经完成后才继续：App 认证或 unknown 暂停调用 `pua_screen(action="resume")`，设备锁屏则重验 READY，成功时自动恢复对应锁屏暂停；等待经过一段时间不等于完成或授权恢复。然后获取一次新观察，同时准备下一步并判断正确前台 App、认证提示及当前目标页。用户可能切换了 App、返回上层、滚动或顺带完成后续操作，因此不沿用接管前的坐标、observation_id 或元素 ID。根据新状态查找下一个语义目标；必要时用截图读取受保护页面内容，不为每步重新登录或单独验收。

如果认证仍未完成，指出当前剩余步骤并等待，不执行被阻塞动作。如果用户选择「暂时无法完成」或说明暂时不能认证，说明已完成和剩余范围，保留接管检查点；用户取消时停止后续操作。若手机或通道失效，按 setup skill 恢复 READY，直接复用其中的新观察继续准备下一步；不能把 App 会话过期误当成服务需要重启。

根据新状态继续剩余已授权工作。用户接管期间已完成的提交必须先回读结果，不能重复发送、支付、下单或重放整个输入 / 批次。认证完成不代表原任务完成；最终仍须核对全部 App、字段、覆盖范围和输出文件。
